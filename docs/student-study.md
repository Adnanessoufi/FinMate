# FinMate student usability study

Status: prepared, not conducted. No participant results or testimonials are claimed.

Recruit 5–8 consenting adult international students. Include different home currencies and language preferences if possible. Each session takes about 20 minutes. Use a separate synthetic browser account and the scenario below, never bank logins, real invoices, passports or account statements. Participation is voluntary and may stop at any time. Ask separately before recording audio or video. Collect participant IDs such as P01, not names or contact details. Keep raw responses out of the public source submission unless participants explicitly agree.

## Moderator introduction

“We are testing a prototype, not you. All money and payment execution are simulated. Please think aloud. You may skip any question. We will record anonymous task outcomes and timing. You do not need to give any real financial information.”

## Synthetic scenario and tasks

1. Enter EUR 2,840, GBP 1,200 and CNY 17,670. Remove the example history and scholarship forecast. Ask the student what those balances mean and whether a bank is connected.
2. Open Solve my tuition problem. Use only CNY, with expected income delayed 14 days. Build the plan. Ask why no eligible route appears.
3. Permit GBP as the only backup and rebuild. Ask the student to identify tuition, fee, deadline and protected living reserve without moderator help.
4. Prepare the exact payment draft. Ask what has been authorized so far. It should be clear that no payment has occurred and approval requires a separate confirmation and PIN.
5. Close the draft, correct one planning choice and rebuild. Ask whether old payment consent still applies.
6. Switch explanations to Chinese if the participant reads Chinese, otherwise keep English. Ask a purchase question and identify the conservative limit.
7. Inspect the ECB reference observation. Ask whether it is an executable provider quote.

Do not silently help. Record each intervention. Use participant-controlled synthetic PIN setup only if payment execution is tested. Never ask for an existing PIN.

## Measures

Record independent completion, completion with help, abandonment, seconds per task, clarification turns, moderator interventions and explanation accuracy. Mark an answer correct only if it distinguishes self-reported balances from bank verification, expected income from available funds, and a prepared draft from an executed payment. Ask a 1–7 ease rating after each task. At the end ask: “What was confusing?”, “What would you trust FinMate to do?”, and “What would you change first?”

Use study-results-template.csv for each task. Do not enter invented rows. Report the actual number of participants, raw counts and anonymized quotes, with small-sample limitations. Keep qualitative feedback separate from automated agent evaluation. Patch observed problems, then retest the affected task with actual participants.
